# 0.5.1 Beta

This patch improves Database Browser responsiveness. It remains a beta, not a fully tested production release. Keep independent backups before updating or changing important data.

## Improvements

- Returning to Database Browser restores the selected database, table, view, filters, sort order, and page.
- Recent rows, table structure, and table statistics are reused for up to 30 seconds. Database and table lists are reused for up to two minutes.
- Navigating away during a read and returning shares the pending request instead of starting a duplicate query.
- Columns and Indexes do not fetch rows until Rows is opened.
- Refresh fetches current database and table lists along with the selected view, including changes made outside the app.

## Cache Safety

- Cached results stay in memory, with an entry limit and an approximate 8 MiB retained-data budget. Oversized results are displayed without being cached.
- Login and workspace changes discard the cache. Editing state and mutation approvals are never restored from it.
- Row edits, administration, SQL execution, restore attempts, user changes, and MariaDB service/installer actions invalidate cached reads. Failed operations invalidate them too because some SQL batches can partially commit.
- Cached row pages are keyed by query and column layout. Existing backend schema, original-row, confirmation, and permission checks remain in place for writes.

## Validation And Limits

- Frontend regression tests cover cache expiry, request sharing, bounded retention, session isolation, and invalidation after partial failures.
- Browser workflows cover repeat navigation, restored filters/pages, lazy structure views, editing, refresh, and credential changes.
- With simulated 150 ms database-call latency, a local browser test measured approximately 0.87 seconds for a cold load and 0.11 seconds for reopening, with no repeated database reads. This is a controlled fixture, not a benchmark of your server or a guarantee of live performance.
- This patch does not change native database or installer code and does not constitute new end-to-end testing of MariaDB installation, upgrades, restores, Windows Server, or Enhanced FXServer. The [0.5.0 validation limits](https://github.com/zoxile/fxserver-installer/blob/v0.5.1/docs/releases/v0.5.0.md#validation-limits) still apply.
- The installer remains unsigned. Fully quit the app before running the new installer.
